## Defects and fixes

### D4 — host paths projected into the review surface

- **Manifest:** `factory/evidence.py::_environment_snapshot` now records the
  environment file **repo-relative** (`path`, `path_rel`, `origin`, `sha256`);
  an absolute host path in `environment.*.path` now fails evidence validation.
  The real gate manifest for the re-pilot contains **0** occurrences of
  `/Users/`.
- **Prompt:** the sandbox reviewer config sets `agent.coding_context: "off"`.
  Without it, Hermes builds the coding-posture workspace block and prints the
  host candidate root in the system prompt (measured on the H1 install:
  `auto → host_workspace_visible=True`, `off → False`). The host session cwd
  stays in the factory artifact tree, and the assignment names `/evidence`
  paths only.
- **Constraint, stated honestly:** Hermes `gateway/session_policy.py::build_policy`
  refuses a session cwd that is not an existing **host** directory, so the
  reviewer's host process cwd cannot literally be `/evidence/candidate`. What
  changed is the surface the model can see: no host workspace block and no host
  paths in the manifest. The audit rule is byte-identical and still refuses any
  tool path outside `/evidence`; a model `approve` never overrides it.
- **Reviewer prompt:** it now names the only readable roots and explicitly
  forbids `/`, `/spec.md`, `/workspace`, `/input`, `/review`.

### D1 — frozen harness root ordering

`Pilot.write_status()` no longer creates the root; `Pilot.execute()` calls
`prepare()` first. Regression: fresh root reaches the first admission step;
status write without a root raises; a second `prepare()` still refuses.

### D2 — review wait signal

Review completion is the reviewer transcript's terminal `result` event **or**
`review-result.json`, whichever arrives first, both scoped to the operation key.
A stale result from another key is ignored; a crashed reviewer without a result
still holds.

### D3 — cross-attempt resume semantics

A new claim for the same task+run is an explicit, closed reason
`cross_attempt_resume_unsupported` (mapped to `hold_operator`), not a silent
authorization and no longer indistinguishable from a forgery. Same-lock resume
is unchanged; other run/task remains `stale_attempt`; the board's live-run check
still runs after the grant check. Cross-attempt recovery is documented as
unsupported; recovery must happen inside the attempt that owns the grant.

### Worker/board separation (found by the re-pilot)

The first re-pilot attempt showed the real `factory-runner` worker discovering
the isolated board DB from the run root and completing its own card with
`--force`, after which the graph correctly refused the next resume
(`stale_attempt`). The fix is bounded: the implementation assignment no longer
hands the worker the card id and explicitly forbids Kanban commands, and the
worker session is launched with `-t terminal,file` so the Kanban toolset is not
loaded. The graph's board-ownership fence remains the enforcement point.

## Non-blocking limitations

- The live duplicate-run and premature-resume refusals were proven in the
  earlier Stage 3 attempt and remain covered by the shipped CLI e2e tests; the
  re-pilot's supervisor did not re-run those probes after the review reached a
  terminal state.
- Live cancellation was not re-exercised; the adapter cancellation tests and
  the prior Stage 3 cancellation controls remain the evidence.
- The implementation worker is a host process (trusted): it has a terminal and
  could still shell out to the board. It has no Kanban toolset and an explicit
  prohibition, and the graph refuses any board state change by its own fence;
  this is not whole-agent containment.
- Historical baseline for the Stage 5 measurement is unavailable; the pilot
  reports observed values only (`metrics.baseline.available=false`).
